Q.4) Define Capacity Planning in the context of cloud computing. What parameters are typically evaluated during this process?
1. Exam-Ready Detailed Answer (English)

Definition of Capacity Planning in Cloud Computing:

In cloud computing, Capacity Planning is the systematic process of predicting, determining, and provisioning the optimal amount of computing resources (such as CPU, memory, storage, and network bandwidth) required to meet current and future application workload demands while maintaining Service Level Agreements (SLAs) and minimizing operational costs.

The primary goal of cloud capacity planning is to eliminate two major risks:

  • Under-provisioning: Having fewer resources than required, leading to slow response times, server crashes, and downtime during traffic spikes.
  • Over-provisioning: Allocating excessive resources that remain idle, resulting in unnecessary financial expenditure (high cloud bills).
2. Architectural Diagram: Capacity Planning Process & Evaluated Parameters

Key Parameters Evaluated During Cloud Capacity Planning:

  1. CPU Utilization (Compute Power): Evaluates clock speed, number of vCPUs, and average vs. peak CPU usage percentage (typically keeping threshold around 70%–80%).
  2. Memory (RAM) Consumption: Tracks active memory usage, page faults, Swap usage, and memory leaks for in-memory caches and databases.
  3. Storage Capacity and IOPS: Measures total data growth rate (GB/TB), Read/Write throughput, and Input/Output Operations Per Second (IOPS) for disk latency.
  4. Network Bandwidth and Latency: Evaluates incoming/outgoing traffic (Mbps/Gbps), packet loss, and Round-Trip Time (RTT) between users and data centers.
  5. Application Workload & Concurrency: Analyzes concurrent active users, requests per second (RPS), and seasonal traffic spikes (e.g., festival sales or exam results).
  6. Service Level Agreements (SLAs) & Budget Constraints: Evaluates required uptime (e.g., 99.99% availability), Recovery Time Objective (RTO), and financial budget limits.

Q.1 Descriptive (CO-03) - 6 Marks Bloom's Level: BL-1
Q.1) Describe the importance of Cloud Scaling and differentiate between vertical scaling and horizontal scaling with appropriate examples.
1. Exam-Ready Detailed Answer (English)

Importance of Cloud Scaling:

Cloud Scaling is the ability of a cloud system to dynamically increase or decrease its computing resources (CPU, RAM, storage, servers) in response to changing workload demands. It is crucial for:

  • Maintaining Performance: Prevents application slowdown or crashes during sudden traffic surges.
  • Cost Optimization: Resources can be scaled down during low-traffic hours, saving money via pay-as-you-go billing.
  • High Availability & Reliability: Ensures seamless user experience and business continuity.
2. Diagram: Vertical Scaling (Scale Up) vs. Horizontal Scaling (Scale Out)
Feature Vertical Scaling (Scaling Up) Horizontal Scaling (Scaling Out)
Definition Increasing the capacity (CPU, RAM, Disk) of an existing single server/VM. Adding more server instances/nodes to the existing pool to distribute load.
Downtime Often requires server reboot/restart (causes brief downtime). Zero downtime; new instances are added seamlessly behind a Load Balancer.
Fault Tolerance Single Point of Failure (if the single machine fails, the app goes down). High fault tolerance (if one VM fails, other VMs handle the traffic).
Hardware Limit Limited by the maximum capacity of the physical host machine. Virtually limitless scaling using cloud Auto-Scaling groups.
Example Upgrading an AWS EC2 instance from t3.medium to t3.2xlarge. Adding 5 more t3.medium EC2 instances behind an Elastic Load Balancer.
3. Hinglish Explanation

Himesh Bhai, Vertical vs Horizontal Scaling ka simple logic:

  • Vertical Scaling (Scale Up): Maan lo aapke paas ek delivery boy hai jo cycle chalata hai. Load badhne par aapne usko cycle ki jagah Bada Truck de diya. Machine wahi ek hai, bas uski power (RAM/CPU) badha di! Problem kya hai? Agar woh ek truck kharab ho gaya toh kaam ruk jayega.
  • Horizontal Scaling (Scale Out): Ek bada truck lene ki jagah aapne 10 aur delivery boys rakh liye! Ab agar ek bimar bhi pad jaye, toh baaki 9 kaam sambhal lenge. Cloud computing mein Horizontal Scaling sabse best maana jaata hai.
Q.2 Descriptive (CO-03) - 6 Marks Bloom's Level: BL-3
Q.2) Given a scenario where a cloud service is experiencing performance degradation during traffic spikes, explain how auto-scaling policies can be applied to maintain performance and reliability.
1. Exam-Ready Detailed Answer (English)

When a cloud application faces sudden traffic spikes (e.g., flash sales or breaking news), static servers become overloaded, causing high response times and HTTP 5xx errors. Auto-Scaling resolves this by automatically adjusting the number of active compute instances based on real-time demand.

2. Diagram: Auto-Scaling Architecture During Traffic Spikes

Types of Auto-Scaling Policies to Apply:

  • 1. Target Tracking Scaling Policy: Maintains a specific metric at a target value (e.g., "Keep average CPU utilization of the Auto-Scaling Group at 70%").
  • 2. Step Scaling Policy: Adds resources in steps based on alarm breach severity (e.g., if CPU > 75%, add 2 VMs; if CPU > 90%, add 5 VMs immediately).
  • 3. Scheduled Scaling Policy: Proactively scales out resources before predictable traffic spikes (e.g., scaling up at 9:50 AM before a 10:00 AM flash sale).
  • 4. Cooldown Period & Health Checks: Cooldown prevents rapid thrashing of VMs, and Load Balancer health checks automatically replace unhealthy/crashed instances.
3. Hinglish Explanation

Himesh Bhai, Traffic Spike mein Auto-Scaling kaise bachaata hai:

Jab website par achanak hazaron log aa jaate hain, toh Cloud Monitor (jaise AWS CloudWatch) dekhta hai ki CPU usage 75% ke upar chala gaya hai. Woh turant Auto-Scaling Policy ko signal bhejta hai, jo bina kisi human intervention ke naye Virtual Machines (VM 3, VM 4) launch kar deta hai aur Load Balancer saara traffic barabar baant deta hai. Jab raat ko traffic kam hota hai, toh woh extra VMs ko band (Scale-In) kar deta hai taaki paise bachein!

Q.3 Descriptive (CO-03) - 6 Marks Bloom's Level: BL-5
Q.3) Critically analyse the impact of poor capacity planning on enterprise cloud performance. What strategies would you recommend to improve resource utilization?
1. Exam-Ready Detailed Answer (English)

Impact of Poor Capacity Planning on Enterprise Cloud Performance:

  • Performance Bottlenecks & Downtime (Under-provisioning): Insufficient CPU/RAM leads to high latency, request timeouts, system crashes, SLA violations, and loss of customer trust.
  • Financial Wastage / Cloud Sprawl (Over-provisioning): Running oversized or idle instances ("zombie servers") drastically inflates monthly OpEx cloud bills without improving performance.
  • Inability to Handle Peak Loads: Lack of stress baselines causes cascading failures across microservices during peak business hours.
2. Diagram: Over-Provisioning vs. Under-Provisioning vs. Optimal Utilization

Recommended Strategies to Improve Resource Utilization:

  1. Right-Sizing Instances: Continuously monitor CPU/RAM metrics and downgrade oversized VMs to match actual usage.
  2. Dynamic Auto-Scaling & Serverless Computing: Use Auto-Scaling Groups and FaaS (e.g., AWS Lambda) so resources run only when requests arrive.
  3. Containerization (Docker & Kubernetes): Pack multiple microservices efficiently onto shared host nodes using Kubernetes pod auto-scaling.
  4. Eliminating Idle Resources: Automate scripts to shut down Dev/Test environments during nights and weekends.
  5. Using Spot / Reserved Instances: Use Reserved Instances for predictable baseline loads and Spot Instances for fault-tolerant batch jobs.
3. Hinglish Explanation

Himesh Bhai, Poor Capacity Planning ke 2 bade nuksaan aur unka ilaaj:

  • Nuksaan 1 (Under-provisioning): Zaroorat se kam server liye toh website slow ho jayegi ya crash ho jayegi, jisse customers bhaag jayenge.
  • Nuksaan 2 (Over-provisioning): Dar ke maare zaroorat se bohot bade servers le liye jo 90% time khaali pade rehte hain — isse company ka cloud bill lakho mein aayega!
  • Ilaaj (Strategies): Sahi size ka server chuno (Right-sizing), Auto-scaling aur Docker/Kubernetes use karo, aur raat ko jab office band ho tab testing servers ko auto-shutdown kar do!
Q.5 Descriptive (CO-03) - 6 Marks Bloom's Level: BL-5
Q.5) Assess the effectiveness of Database as a Service in handling large-scale applications for enterprises. What are its advantages and potential risks from a data governance perspective?
1. Exam-Ready Detailed Answer (English)

Database as a Service (DBaaS) (e.g., Amazon RDS, Google Cloud Spanner, Azure SQL, MongoDB Atlas) is a managed cloud service model that enables enterprises to deploy, operate, and scale databases without manually managing physical hardware, OS patches, or backup configurations.

2. Diagram: Enterprise DBaaS Architecture & Governance

Advantages of DBaaS for Large-Scale Applications:

  • Automated Administration: Automated OS/DB patching, point-in-time backups, and automated multi-AZ failover.
  • High Scalability: Supports read-replicas and sharding to handle millions of concurrent queries with low latency.
  • Cost Efficiency & Rapid Deployment: Eliminates upfront hardware CapEx and provisions production-ready databases in minutes.

Potential Risks from a Data Governance Perspective:

  • Data Sovereignty & Residency Compliance: Replicating data across global regions may violate local regulations (e.g., RBI data localization, GDPR, HIPAA).
  • Data Privacy & Multi-Tenancy Risks: Sensitive enterprise data resides on third-party infrastructure, requiring strict encryption at rest and in transit.
  • Vendor Lock-in: Proprietary cloud databases (e.g., AWS Aurora or DynamoDB) make migrating to another provider complex and costly.
  • Limited Administrative Control: Enterprises lack root access to the underlying host OS for custom security auditing tools.
3. Hinglish Explanation

Himesh Bhai, DBaaS aur Data Governance ka simple breakdown:

  • DBaaS kya hai? Database ko khud install, backup aur update karne ki tension lene ki jagah cloud provider (jaise AWS RDS) se ready-made managed database le lena.
  • Fayde (Advantages): Automatic backup hota hai, server crash hone par Standby Replica turant chalu ho jaata hai, aur lakho users ka load aasani se handle hota hai.
  • Data Governance Risks (Khatre): Sabse bada risk hai Data Location (Residency) — jaise RBI ka rule hai ki Indian banking data India ke bahar ke server par nahi jaana chahiye. Dusra risk hai Vendor Lock-in (ek cloud se dusre cloud par database shift karna mushkil hota hai) aur Data Privacy.
